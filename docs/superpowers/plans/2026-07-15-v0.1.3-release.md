# v0.1.3 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the merged Codex window fix as a verified v0.1.3 release with an SSH-signed annotated tag and GitHub Release.

**Architecture:** Make the version bump through a tested feature branch and pull request. After merge, sign the exact synchronized `main` commit locally, verify the signature before pushing, and create a GitHub Release that reuses the verified remote tag.

**Tech Stack:** JSON, Python 3 stdlib `unittest`, Qt 6 `qmllint`, Git SSH signing, GitHub CLI.

## Global Constraints

- Release version is exactly `0.1.3`; tag name is exactly `v0.1.3`.
- Do not add widget behavior or release assets.
- Do not create or push an unsigned tag.
- Stop on any failed test, signature check, merge check, or commit mismatch.
- Use `~/.ssh/id_bdgraue_github` only after confirming its public key matches the private key.
- Register only `~/.ssh/id_bdgraue_github.pub` with GitHub if a signing-key registration is required.

### Task 3: Configure and verify SSH tag signing

**Files:**
- No repository file changes.

**Interfaces:**
- Consumes: `~/.ssh/id_bdgraue_github` and `.pub`, merged `main` commit.
- Produces: locally verified signed annotated tag `v0.1.3`.

- [ ] **Step 1: Verify key pairing**

Derive the public key from the private key with `ssh-keygen -y` and compare its fingerprint to `~/.ssh/id_bdgraue_github.pub`. Stop if they differ.

- [ ] **Step 2: Ensure GitHub signing-key registration**

Query GitHub signing keys. If the public-key fingerprint is absent, add `~/.ssh/id_bdgraue_github.pub` with `gh ssh-key add --type signing --title "Codex release signing"` and confirm it appears.

- [ ] **Step 3: Configure repository-local SSH signing**

Set repository-local `gpg.format=ssh`, `user.signingkey=~/.ssh/id_bdgraue_github.pub`, and a repository-local `gpg.ssh.allowedSignersFile` containing the configured Git email and public key. Do not change global Git configuration.

- [ ] **Step 4: Create and verify tag**

Create `v0.1.3` with `git tag -s -a v0.1.3 -m "AI Usage v0.1.3 — dynamic Codex rate-limit windows"`, verify it with `git tag -v v0.1.3`, and assert `v0.1.3^{}` equals synchronized `main`.

### Task 4: Publish and verify GitHub Release

**Files:**
- No repository file changes.

**Interfaces:**
- Consumes: locally verified `v0.1.3` tag.
- Produces: remote tag and published GitHub Release `v0.1.3`.

- [ ] **Step 1: Push only the verified tag**
