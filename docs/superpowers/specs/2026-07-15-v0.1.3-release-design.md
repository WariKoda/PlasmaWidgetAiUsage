# v0.1.3 Release Design

## Goal

Publish the already merged dynamic Codex rate-limit window fix as a complete
v0.1.3 patch release with a verified version bump, a reviewed release commit,
an SSH-signed annotated Git tag, and a published GitHub Release.

## Release Contents

The release contains the six commits after v0.1.2, centered on deriving Codex
window keys and labels from the server-reported `window_minutes`. It also
includes the approved design, tests, documentation updates, and local-worktree
ignore rule that accompanied that fix. No additional widget behavior is added
during the release process.

## Version and Branch Flow

1. Work on the `release-v0.1.3` feature branch.
2. Change `KPlugin.Version` in `package/metadata.json` from `0.1.2` to `0.1.3`.
3. Run the complete Python, JSON, live-provider, and Qt 6 QML checks.
4. Commit the version bump and push the feature branch.
5. Create a pull request to `main` and merge it only after checks succeed.
6. Fast-forward local `main` to the verified merge commit.

## Tag Signing

Use the existing `~/.ssh/id_bdgraue_github` identity with Git's SSH signing
format. Before tagging, verify that the private key is usable and that the
matching public key is registered with GitHub as a signing key. If it is not
registered, add only `~/.ssh/id_bdgraue_github.pub` through `gh ssh-key add
--type signing`.

Create `v0.1.3` as an annotated, SSH-signed tag pointing exactly at the merged
`main` commit. Verify the signature locally before pushing. If signing or
verification fails, stop; do not substitute an unsigned tag.

## GitHub Release

Push the verified tag, then create a non-draft GitHub Release named `v0.1.3`.
Use GitHub-generated release notes starting after `v0.1.2`, and verify that the
published release points to the same tag and commit. Do not attach generated
packages because the repository has no established release-asset workflow.

## Verification and Failure Handling

Before the release commit:

- run all `unittest` tests;
- compile `package/contents/code/ai-usage-json`;
- parse `package/metadata.json`;
- inspect live Codex helper output;
- run Qt 6 `qmllint` and require exit code zero;
- require a clean diff check.

Before publishing:

- require the release PR to be merged;
- require local `main` to equal `origin/main`;
- require `package/metadata.json` to report `0.1.3`;
- require `git tag -v v0.1.3` to verify successfully;
- require the remote tag and GitHub Release to resolve to the merged commit.

Any failed prerequisite stops the release rather than producing a partial,
unsigned, or incorrectly targeted version.
